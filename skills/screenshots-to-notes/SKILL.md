# 截图 → 学习笔记

**范例成品**：`D:\倒立摆_参数整定\study_video-notes.md`（45 张图，6 个批次）。
不确定格式该长什么样时，先读它的前 200 行。

## 为什么要按这个流程

2026-09-18 第一次做时，单个 agent 直接读 4032px 原图，**5 张图就烧掉 120K token**，
做到一半上下文就撑不住了。后来改成「先压图 → 分批 → 每批一个子 agent → 合并」才跑完。
下面每一步都是为了避免这个问题，不要省略。

## 流程

### 1. 预处理（必做，在主对话里跑脚本）

```powershell
python "$env:USERPROFILE\.claude\skills\screenshots-to-notes\scripts\prep_images.py" prep "<图片目录>" --out "<笔记目录>\images"
```

- 按 EXIF 方向转正（手机横拍、倒拍的照片很常见，上次 45 张里有 12 张是倒的）
- 长边压到 1600px、转成 jpg，存进 `images/`。**笔记嵌入的就是这些图，原图不动**
- HEIC 需要 `pillow-heif`；脚本发现缺少时会提示安装命令，**先问用户再 `pip install`**
- 可以一次传多个目录（如 `new_images1 new_images2`）
- 结果写进 `images/manifest.json`，里面有建议的分批方案（`batches`）

脚本只打印 ASCII，中文信息都在 manifest 里，用 Read 工具读（本机 ACP=1252，控制台会把中文变成 `?`）。

### 2. 确认分批

读 `manifest.json` 的 `batches`。脚本先按**文件编号跳号**和**拍摄时间间隔**切出"一次录课"，
太长的平均拆开（每批不超过 8 张），不足 3 张的零头并进上一批。再人工看一眼：

- 同一张框图逐步加批注的连续几帧应该在**同一批**；如果被切开了，手动挪一下
- 批次命名 `0, A, B, C…`，按内容顺序排

**只有 1 批（大约 10 张以内）时，跳过第 3 步，直接在主对话里按子 agent 模板的规则自己写
`_part_0.md`。** 图已经压到 1600px，10 张放得下；再派子 agent 只会多一份启动开销。

**有多批时**，把分批方案（批次名 → 图片范围 → 主题）**告诉用户后再开跑**，用户可能知道哪些图属于同一节。
主题只看每批**第一张**图来判断，看不出就写"未知"。主对话要是把每张图都看一遍，
子 agent 又会再读一遍，等于花两份 token。

### 3. 每批一个子 agent（并行）

- 每批派一个 Agent，`model: "sonnet"`，在同一条消息里一起派出
- prompt 用 [references/batch-agent-prompt.md](references/batch-agent-prompt.md) 的模板，填入图片列表、
  上下文（课程名、用户目标）、输出路径 `<笔记目录>\_parts\_part_<批次>.md`、
  原图目录（只读）和放大图的临时目录（用 scratchpad）
- 如果用户给了"最终要复现什么"（比如在 MATLAB 里复现推导），也写进 prompt，
  子 agent 会按这个目标决定写多细

### 4. 检查分段稿，有问题的批次重读

子 agent 全部返回后，先读各 `_part_*.md` 的「本批存疑汇总」：

- 某批错字很多、或和相邻批次衔接不上 → **先重读这一批再合并**（用户上次就要求"先重读 E 再合并"）
- 重读前把旧稿备份成 `_part_X.old.md`
- 公式里某个字符要放大看时，用 crop 截局部，不要整张重读：
  ```powershell
  python "...\prep_images.py" crop "<原图>" 0.4 0.3 0.7 0.5 --out "<scratchpad>\zoom.png"
  ```
  四个数是左、上、右、下的比例（0~1）

### 5. 合并

按 [references/note-layout.md](references/note-layout.md) 的结构，分两步：

1. **手写** `_parts/_front.md`：使用说明 + **核对清单** + 关键结论速查 + 路线图 + 逻辑断层汇总。
   核对清单和断层汇总来自各分段稿末尾的「本批存疑汇总」「本批逻辑断层」，按 A/B/C 重新编号
2. **用脚本拼接**，不要手写拼接代码：
   ```powershell
   python "$env:USERPROFILE\.claude\skills\screenshots-to-notes\scripts\prep_images.py" merge "<笔记目录>" --name <笔记名>.md
   ```
   脚本会：备份旧笔记为 `_parts/<笔记名>.prev.md`；按 `0, A, B…` 顺序拼接分段稿（跳过 `.old`）；
   去掉"本文件由批次"那一行和两个汇总节（已经搬进 `_front.md` 了）；
   把分段稿的标题**降一级**，让全文只有 `_front.md` 那一个一级标题

### 6. 交给用户核对，再回填

- 告诉用户：核对清单在笔记开头，标了几处【看不清】、几处内容存疑
- 用户核对时，一般会**直接在清单每一条下面写一行解释**。他说"我写好了"时，去读这些新增的行
- 按用户的解释改正文，把清单标题改成「✅ 核对说明（已全部核实）」，每一条后面写上结论。
  这些条目保留下来作为记录，不要删掉
- 如果笔记服务于某个项目，在那个项目的 `CLAUDE.md` 里加一行指针，指向笔记路径

## 硬性规则

1. **看不清就标【看不清】，不要猜。** 能看出大致形状的，写成"形似 X"并说明为什么不确定。
   用户上次明确要求："看不清就标注，不要猜。我会重新检查标了【看不清】的地方。"
2. 不确定的地方分**三类**标注，不要混在一起：
   - **A 内容存疑**：字看清了，但推导或数值看起来有问题（符号方向反了、数值无故跳变）。优先级最高
   - **B 字符看不清**：真的认不出字
   - **C 标注含义不明**：圆圈、箭头、圆点这类没配文字的强调符号
3. **逻辑断层照实写出来，不要自己补。** 老师"直接给出"的结论就写"直接给出"，
   不要替老师编推导过程。可以另起一段写"可能的依据"，但要标成推测。
4. **弹幕、观众评论和老师原话分开写**，弹幕要标明是弹幕。弹幕里的字看不清时归入 B 类，
   弹幕提出的质疑放进「逻辑断层汇总」末尾。
5. 每一小节都在附近嵌入对应的图：`> 来源：IMG_xxxx` 加 `![IMG_xxxx](images/IMG_xxxx.jpg)`。
6. 公式用 `$...$` / `$$...$$`。笔记开头要提醒用户在 Typora 里打开「内联公式」并**重启**。
